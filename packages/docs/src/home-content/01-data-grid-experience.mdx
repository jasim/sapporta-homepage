## A datagrid for every table

Declare a table and you get a live, editable grid. The demo at the top of
this page came from one table declaration.

**Why spreadsheets work.** People reach for spreadsheets because they can
work with data without deciding every requirement in advance. Sorting,
searching, and filtering are available on every sheet, and that small set of
operations covers much of what you need to change and understand data.

**One component, done well.** Traditional ERP interfaces are mostly forms,
data grids, and reports — keyboard-first, information-dense, built for power
users. Sapporta brings that to the web by using one data grid for all tabular
data, so the work put into that component benefits the whole application.

**No second-class tables.** Built per feature, grid behavior gets written
again for every table, so conventional systems polish a few central screens
and leave the rest of the application's data poorly served. In Sapporta, like in a spreadsheet, every table gets the full
grid the moment it is created.

**The grid itself.** The
[Sapporta Grid](https://github.com/jasim/sapporta/tree/main/packages/grid) is
a custom-built React component with a feature set and UX similar to Airtable
and NocoDB, with keyboard support that works across nested levels.
