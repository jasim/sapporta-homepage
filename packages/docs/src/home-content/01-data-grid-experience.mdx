## A datagrid for every table

Declare a table and a live, editable grid exists — the demo at the top of
this page is exactly that, produced by one table declaration.

**The spreadsheet lesson.** People reach for spreadsheets because they can
work with data without anticipating every requirement in advance. Sorting,
searching, and filtering are available to every sheet, and together they form
a partial but high-leverage algebra for changing and understanding data.

**One surface, polished deeply.** Traditional ERP interfaces are largely
forms, data grids, and reports — keyboard-first, information-dense, built for
power users. Sapporta brings that experience to the web by using the data
grid as the universal surface for tabular data, so the heart and soul put
into one component benefits the entire application.

**No second-class tables.** Built as one-off features, grid behaviors have to
be defined from scratch for every table — even with an LLM. So conventional
systems polish the few central screens and the rest of the application's data
becomes a second-class citizen. In Sapporta, like a spreadsheet, every table
gets the full grid the moment it is created.

**Built to be composed and extended.** The
[Sapporta Grid](https://github.com/jasim/sapporta/tree/main/packages/grid) is
a custom-built React component with a feature set and UX similar to Airtable
and NocoDB: paginated, filterable, sortable, and searchable, with nested
master-detail relationships and keyboard support that works across levels.
